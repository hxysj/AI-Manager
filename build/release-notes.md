## 2.0.10 变更说明

### 优化窗口关闭响应

- 将当前窗口关闭动作缓存为独立的异步读状态。保存设置或切换关闭行为后会同步更新缓存，关闭窗口时不再为了读取配置等待主状态锁。
- 选择“最小化”时先立即隐藏主窗口，再在后台同步快捷切换窗口状态；快捷切换窗口的同步不再阻塞主窗口关闭流程，减少点击关闭后无响应或延迟隐藏的问题。
- 保留“退出”和关闭确认对话框的原有行为，只有关闭动作配置读取和快捷切换同步改为异步处理，不改变用户的关闭选择。

### 完善 Token 用量展示

- 新增共享 `TokenCount` 展示组件，统一 Usage、Provider、Skill Usage 和快捷切换面板中的 Token 数字格式，避免不同页面使用不同的单位和精度。
- 千级 Token 使用两位小数的 `k` 单位，百万级使用两位小数的 `M` 单位，同时显示带千位分隔符的精确值；接近百万的数值统一切换到 `M` 展示，避免 `999.95k` 与 `1.00M` 之间出现明显跳变。
- TokenCount 会继承所在页面的字号和字重，并单独缩小精确值，保证统计卡片、表格、图表提示、Provider 详情和导出长图在紧凑布局中仍能完整显示。
- Skill Usage 列表改为优先按实际 Token 消耗降序排列，同耗用量时按 Skill 名称排序，便于快速定位高消耗 Skill。
- Usage 解析支持 Codex 新增的 `custom_tool_call.input` 字段。通过自定义工具调用触发的 Skill 现在可以被正确识别并计入 Skill 用量统计，不再只支持传统 `function_call.arguments`。

### 修复 Codex Ultra 多 Agent 用量重复统计

- Codex Ultra 会为同一个根线程创建多个子 Agent 日志。Usage 刷新时识别 `thread_source: subagent` 和子 Agent 来源元数据，只统计根线程，避免把多个 Agent 的重复累计 Token 当成多次真实消耗。
- 刷新过程中会删除历史数据库中已记录的子 Agent 用量及对应索引，因此升级后重新打开或刷新 Usage 即可修正此前被放大的统计结果。
- Sessions 仍保留子 Agent 会话的扫描和展示能力，修复只作用于 Usage 统计口径，不影响会话查看。
