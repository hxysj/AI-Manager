## 2.0.11 变更说明

### 修复 Codex 子 Agent 用量统计口径

- Codex 子 Agent 会话不再被整体排除。统计器会识别 v1 独立子线程和新版分叉快照，在分叉点保留父线程累计值作为计算基线，只记录子 Agent 实际新增的输入、缓存命中和输出 Token，避免少算真正由子 Agent 产生的消耗。
- 子 Agent 完成首轮任务后继续执行的后续轮次也会保留，不再因为只截取首次任务而遗漏后续 Token；分叉快照中继承的父任务记录仍会被排除，防止父线程和子线程重复计费。
- Codex 累计计数器保持不变时不再生成重复用量记录；当累计计数器发生重置时，改用当前事件携带的单次用量恢复增量，兼容长会话及不同 Codex 日志版本。
- 增加 Codex 用量解析器版本管理。统计规则升级后会自动清理旧会话索引并从原始 Session 重建，因此此前少算或重复计算的数据可以通过重新同步恢复，无需手动删除 Usage 数据库。

### 补全 Skill 用量统计

- Skill 用量匹配改为读取全部已定价 Usage 日志，不再只使用默认返回的最近 20 条记录；较早的 Skill 调用现在也能找到对应请求及 Token，解决历史 Skill 有调用次数但没有用量的问题。
- Skill 目录扫描改为递归识别，覆盖普通 Skill 和 `.system` 系统 Skill；插件缓存等未纳入当前托管列表的 Skill，只要会话中存在明确路径或资源标识，也会动态加入统计结果。
- 扩展 Skill 调用识别格式，支持 `/skill-name`、`/plugin:skill`、`$SkillName`、`skill://...`，以及相对或绝对的 `skills/.../SKILL.md` 路径，减少不同 Codex 版本和插件调用方式造成的漏算。
- Skill 调用沿用 Codex 子 Agent 分叉边界，只统计子 Agent 自身真正触发的 Skill，不把分叉文件携带的父线程调用重复计入。
- 新增按会话文件修改时间命中的内存和 SQLite 持久化缓存，并为缓存增加解析器版本失效机制。首次升级会重建一次索引，后续统计只解析新增或变化的 Session，避免每次进入 Skill Usage 都全量读取历史文件。
- Skill Usage 页面会合并筛选器连续变化产生的请求：当前统计尚未完成时只保留最后一次刷新，避免多个全量请求在后端排队并阻塞界面。

### 提升扫描与统计响应速度

- `app:ensure-skills-ready` 和 `app:ensure-sessions-ready` 改为只刷新对应模块，不再先执行完整应用状态重建；`app:ensure-tools-ready` 直接复用当前状态，避免页面切换重复探测所有 CLI、Provider、规则和 Usage 数据。
- 完整状态刷新由两次初始化压缩为一次初始化加运行时 Provider 状态回读，并缓存 CLI 可执行路径和版本探测结果，减少重复运行 `where.exe` 和 `--version` 命令。
- Sessions 列表按文件路径和修改时间复用未变化的元数据。发生变化的活跃 Session 使用单遍轻量扫描提取标题、摘要、模型和消息数量，不再为了列表展示构造完整消息及工具调用集合；完整解析只在用户打开会话详情时执行。
- Codex Usage 和 Skill 调用共享单遍子 Agent 分叉状态解析，并直接读取追加日志中的首个有效时间戳，减少对大型活动 Session 的重复 JSON 解析。
- Skill 挂载状态由逐个串行检查改为并发检查，降低 Skill 数量较多时扫描软链接、源目录和 CLI 目标的等待时间。
- 应用调用日志由每次完整读取并重写 JSON 数组改为 JSONL 追加写入，超过阈值后才压缩保留最新 1000 条；旧日志会自动转换，日志读取顺序和清空行为保持不变。
- 在当前开发数据上的复测中，Sessions 扫描由约 6.5 秒降至 117 毫秒，Usage 同步由约 7.0 秒降至 0.6 秒左右，Skills 扫描由约 3.0 秒降至首次 799 毫秒、缓存后 266 毫秒；同时缩短了慢请求占用全局状态锁时其他接口的排队时间。

### 优化 Token 趋势图刻度

- Token 趋势图 Y 轴只显示 `k`、`M` 等紧凑值，不再在刻度后附带括号和完整精确数字，减少长数值挤占图表绘制区域。
- Tooltip、统计卡片和其他需要核对明细的位置仍保留带千位分隔符的精确 Token，图表更易阅读的同时不会丢失可核对数据。
